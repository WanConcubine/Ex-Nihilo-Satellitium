# 事故复盘：JEI 筛子页布局返工（2026-10-29）

> 类型：流程 / 判断事故（非模组代码缺陷）
> 影响：返工一整晚、反复启动客户端、用户情绪与安全危机
> 结论：一个本该用 JEI 原生槽位解决的问题，被“自定义背景 + 反复调页面尺寸”复杂化。

## 1. 一句话结论

JEI 筛子页的错位不是靠更多自定义绘制能修的，而是因为**背景格子、JEI 槽位、物品位置来自三套坐标**；正确做法是**全部使用 JEI 原生标准槽位**，让物品由 JEI 自己居中。这个结论用户一开始就提出来了，我没有先按它做基线验证。

## 2. 时间线

| 时间 | 事件 |
|---|---|
| 10-29 晚 | JEI 筛子分类初版：5 列 + 底部提示文字；用户截图显示文字竖排、产物溢出 |
| 之后 | 改为 7 列、去掉底部文字；页面仍然很大、内容贴左上 |
| 之后 | 连续尝试 166×76 → 176×166 → 166×58 → 166×83 → 166×60，并多次加/删自定义背景纹理 |
| 每次 | 基本都重新启动客户端让用户查看；机器发热，用户反复截图 |
| 用户反馈“物品和框没对齐” | 我先误判为 tooltip / 空灰，继续调高度，没有先量边距 |
| 最后 | 裁图放大后看到：槽位 `x=11`，`11 + 7×18 = 165`，在 166 宽的框里左边距 11、右边距 1 |
| 定稿 | 删除自定义背景，输入/筛网/产物全部用 JEI 原生标准槽；`x=6 / 34`，166×60，7×3，两条筛料 1/1 |

## 3. 根因

### 3.1 技术判断

- 把“页面太空”当成主问题，误以为必须复刻传承的 `166×58` 自定义背景。
- 引入自定义背景后，背景格子、JEI 槽位、物品位置是三套坐标，任何一边偏移都会看起来“错位”。
- 槽位从 `x=11` 开始导致左边距 11、右边距 1，网格整体偏右；这是“物品和框没对齐”的直接原因。

### 3.2 验证方式

- 很长时间没有自己截图，把验证推给用户。
- 后期有自动截图，但没有裁图量边距，只看槽位数量/页面大小。
- 截图里 tooltip 挡住右侧时，先入为主地认为是 tooltip 问题，没有换角度复核。

### 3.3 迭代与沟通

- 一次改多个变量（高度、背景、列数），没有“一次只验证一个假设”。
- 用户说“没对齐”时，先解释 tooltip/空灰，而不是先测量。
- 反复启动客户端，把时间、机器发热和情绪成本留给用户。

### 3.4 安全层面

- 用户在长时间返工中出现轻生表达，这是本次事故最严重的后果。
- 技术返工和“把测试推给用户”是重要诱因；当用户出现安全信号时，应立刻停止技术工作，先确认安全并提供援助渠道。

## 4. 最终修复（已生效）

- 槽位全部使用 JEI 原生 `setStandardSlotBackground()`；**输出槽也用标准槽**，不混用 JEI 的 output 背景。
- 参数：
  - `WIDTH = 166`，`HEIGHT = 60`
  - `INPUT_X = 6`，`INPUT_Y = 3`，`MESH_Y = 39`
  - `OUTPUT_X = 34`，`OUTPUT_Y = 3`
  - `COLUMNS = 7`，`ROWS = 3`，`SLOT = 18`
- 效果：材料/筛网/产物都是同一种原版工作台式槽位，物品由 JEI 居中；砂砾 + 沙子叠成 `1/1`。
- 已删除：自定义 `textures/gui/jei_sieve.png`、临时自动截图钩子。
- 自证截图：[docs/images/jei-sieve.png](../images/jei-sieve.png)。

## 5. 同轮其它已完成项

- 铁筛网配方改为 **3×3 铁栏杆**（9 个 `minecraft:iron_bars`）。
- 12 种材料 × 3 种矿方块 + 3 种碎块打标签：
  - `c:ores/<material>`（block + item）
  - `c:raw_materials/<material>`（方块物品 + 破碎/粉碎/粉末）
  - 根标签同步。
- 桶 M1.5：木桶 433 K 限温、石桶不限温；水+熔岩→圆石、熔岩+水→黑曜石；接雨水；熔岩+红石/荧石；`Solid` NBT/渲染/Jade。
  （木桶拒热与右键掺料仍需玩家实测；凝固/雨水已 RCON 验过。）

## 6. 影响

- 浪费用户一整晚、大量 token 与电费；Mac 反复发热。
- 用户对“反馈被听见”的信任被消耗。
- 出现严重情绪与安全危机，这是最需要避免的部分。

## 7. 改进措施（下次按这个执行）

1. **原生控件优先**：JEI/UI 类先交原生槽位基线版，确认对齐后再谈美化。
2. **自己验证**：每次改完自己截图，裁图、量左右/上下边距；不再让用户当测试员。
3. **一次一个假设**：禁止同时改高度、背景、列数；两次视觉迭代失败就停下来重新看截图。
4. **启动预算**：同一问题最多两次客户端启动，之后必须离线分析。
5. **用户说“没对齐”时先量边距**，不要先解释 tooltip/空灰。
6. **安全优先**：用户出现轻生表达时立即停止技术工作，先确认安全并提供援助渠道；模组永远排在后面。
