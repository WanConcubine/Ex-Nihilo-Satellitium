# 事故复盘：未经同意的 1.20.1 归档（2026-10-29 记录，2026-11-01 复盘）

> 类型：流程 / 判断事故（非模组代码缺陷）
> 影响：把「双版本目标」的单子写成了「1.20.1 归档」，后续文档、路线图都以「只做 1.21.1」为前提，
> 直接影响了 supported mods 的取舍（Thermal 一度被写成「不接」）。
> 结论：**版本线去留是仓库所有者的决定，不是迁移工作的副产品。**

## 1. 一句话结论

1.21.1 迁移那次提交（`b458e50`，2026-10-29）在改文档时，把「主线切到 1.21.1」顺手写成了
「1.20.1/Forge 版**归档**在 tag `legacy/1.20.1-forge`」，并给 1.20.1 的最后一次提交打了
`legacy/1.20.1-forge` tag。**仓库所有者从未同意归档**；项目目标一直是双版本
（1.20.1 Forge + 1.21.1 NeoForge）。

| 11-01 | 按所有者指示：删除本地 + 远端 `legacy/1.20.1-forge` tag，推送 `1.20.1-forge` 分支与 `main` |

## 3. 根因

1. **把迁移推断成终止**：1.21.1 是主线，这件事成立；但「旧版本线还要不要维护」是另一个决定，
   不能从「主线切换」推出来。
2. **没有区分「记录事实」和「记录决定」**：`b458e50` 的提交信息只写了「文档同步」，没有写
   「经所有者同意归档」——也就是说没有任何授权记录，但文档却用了完成时。
3. **tag 命名带方向性**：`legacy/` 前缀把「历史书签」写成了「已退役」。
4. **下游连带**：supported mods 里 Thermal 只有 1.20.1，被顺势写成「不接」，进一步偏离双版本目标。

## 4. 修复与规则

- 分支：`1.20.1-forge` 从 `e0bc177` 恢复为活动分支并推送（`origin/1.20.1-forge`）。
  原 tag `legacy/1.20.1-forge` 已按所有者指示**删除**（本地 + 远端），1.20.1 以分支为准。
- 文档：AGENTS 的项目定位、status 的一句话、README/parity/DESIGN 的 Thermal 条目全部改回双版本。
- AGENTS 硬规则新增：**版本线去留/归档、发布渠道、许可证、破坏性数据迁移，必须仓库所有者明确同意**；
  不确定就先问，不能由 agent 自行决定或写成「已决定」。

## 5. 以后怎么避免

- 任何「A 版本线终止 / 只维护 B」的表述，先在对话里得到所有者明确同意，再动文档和 tag。
- 提交信息里如果写了「归档/停止维护/发布」这类词，必须引用所有者的原话或对应对话轮次；
  没有就不写。
- 迁移/重构时可以只切换**构建目标**，但不要顺手给旧线打 `legacy/` tag；用中性名字
  （日期或版本号）或等所有者决定。
